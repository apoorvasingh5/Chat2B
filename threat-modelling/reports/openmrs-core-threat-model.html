1. Executive Summary

Overall risk: High

OpenMRS Core is a Java/Spring/Hibernate medical-record platform holding patient health information. The deep dive found 678 service methods guarded by @Authorized privileges and 9 servlet filters, including a pre-authentication first-run setup wizard and a database update wizard that run outside the normal security stack. Authorization appears to be function-level (privilege) only, with no evidence of patient/location scoping. Authentication, session handling, secrets storage, module trust and deployment posture could not be confirmed from the repo and are carried as explicit open questions. All repo-derived facts are heuristic, low-confidence candidates.

Top risks:

  • Setup wizard can take over an uninitialized or reset instance (T-001).
  • Function-level privileges do not guarantee patient-level authorization of PHI (T-003).
  • Dynamically loaded modules run with full platform privileges and no evidenced integrity checks (T-004).
  • Web authentication/session controls and update-wizard authentication are unconfirmed (T-005, T-002).
  • Plaintext runtime credentials and legacy dependencies expand the blast radius (T-008, T-010).

Key recommendations:

  • Restrict the setup/update wizards and pre-provision runtime configuration.
  • Add patient/location-scoped authorization and audit logging of chart access.
  • Sign and verify modules; move secrets out of the properties file; run SCA and upgrade legacy libraries.

Major unknowns:

  • Authentication and session implementation
  • Production exposure and TLS posture
  • Module trust model
  • HL7 transport and authentication
  • REST/FHIR module surface

T-001: Unauthenticated first-run setup wizard can be hijacked to take over a deployment

Component: Startup Filter Chain (Init/Update/Module Filters) · Category: Access Control · STRIDE: Spoofing, Elevation of Privilege, Tampering

CWE: CWE-306, CWE-284 · CAPEC: · ATT&CK:

Related business workflow(s): BP-001/S2 · Violated invariant: INV-001

Affected data: DB credentials, Admin credentials, Patient PHI

Attack scenario: While the runtime properties file is missing, InitializationFilter redirects every request to the setup wizard. An attacker who reaches a fresh or reset instance first supplies attacker-controlled DB settings and an admin password, so the instance is owned before the operator completes setup; if the properties file is deleted or unreadable later, the wizard can re-activate.

Impact: Full administrative takeover; data redirected to an attacker database; later PHI exposure.

Likelihood: Medium · Severity: Critical · Confidence: Medium

Preconditions:

  • Instance reachable from untrusted network before setup completes
  • No runtime properties found, or properties lost/unreadable after deployment

Evidence:

  • REPO:web/src/main/java/org/openmrs/web/filter/initialization/InitializationFilter.java:76-81
  • GRP-008
  • WFRP-001
  • WFRP-006

Assumptions:

  • Wizard access control after first run was not read; the Javadoc describes only the redirect-when-no-properties behavior.

12. Recommended Mitigations

For T-001

Preventive:

  • Disable or bind the setup wizard to localhost after first initialization; require a one-time setup token.

Detective:

  • Alert when the wizard is served or runtime properties change.

Corrective:

  • Rotate admin and DB credentials; rebuild instance from a trusted baseline.

Compensating:

  • Network ACL or reverse proxy that blocks setup paths from untrusted networks.

Preventive:

  • Add lockout/rate limiting to the update wizard; re-verify the authenticated super user on the execute step.
  • Run updates from a maintenance window on an isolated network.

Detective:

  • Log and alert on failed wizard logins.

Corrective:

  • Restore DB from backup if unauthorized changesets ran.

Compensating:

  • Restrict access to the update path by IP allowlist.
